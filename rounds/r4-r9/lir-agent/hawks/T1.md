# Hawk T1: the metareasoning stopping bound

Hawk for eurisko, 2026-10-03 (v2, 07:10Z: adds section 5, a check on the harness's own ShipHunt env,
and verifies the Gao et al. formula; v1 kept at /tmp/lir-agent/T1.v1.md). Item (GOAL.md, "Theory T1" and forecaster signal 4): expected gain
from considering more candidates against a learned forecaster is bounded by the forecaster's
uncertainty (optimizer's curse; Russell-Wefald value of computation). Objection to test: the bound is
vacuous, or needs independence assumptions the policy violates.

**Verdict: RESHAPE.** As stated, the expected result ("optimism gap grows with candidates, so stop
early") is guaranteed by order statistics and carries no information about LIR control masks. The
independence objection is half wrong (the upper bound needs no independence) but the bound is
vacuous at n = 2 on a [0,1] success scale, and three things the policy actually does (adaptive
proposal, optional stopping, shared misbelief) move the measured gap far more than the bound
predicts. Run instead an exogenous-n evaluation on ShipHunt with exact Bayes truth (`bayes_plan`), an explicit
cost per forecast call, a random-pick control and named baselines (section 4). Section 5 shows that on
the harness's own env, with no cost per forecast the true value of the chosen plan never falls with n in
any of 18 configurations, so without a deliberation cost there is nothing for a stopping rule to stop.

All numbers below come from `hawks/T1_sim.json` (made by `hawks/T1_sim.py`, numpy 2.5.3, seed 0,
20000 trials, 1.6 s on one core). The toy: candidate true success probabilities V ~ Beta(2,5), forecast
F = V + error, error sd sigma = 0.15, select argmax F.

## 1. The "bound" is an identity until someone models the gap

Let gap(n) = E[F_sel - V_sel]. Then true gain from candidate n+1 = apparent gain - change in gap.
That is accounting, not a theorem. All the content is in the model of the gap (GOAL.md signal 4, the
learned optimism-gap regressor). The theory item can say nothing more without a distributional
model, and the known ones are:

- Upper bound: E[error at the argmax] <= E[max_i error_i] <= sigma * sqrt(2 ln n) for sigma-sub-Gaussian
  errors with **any** dependence (Jensen plus the union bound). So "requires independence" is wrong
  for the upper bound. Independence (or a known joint Gaussian) is needed only for Smith-Winkler's
  exact shrinkage correction.
- The bound is vacuous at the scale that matters. sigma * sqrt(2 ln 16) = 0.353, while the realised
  gap is 0.165 (independent errors) and 0.039 (correlated errors, rho = 0.8). The decision-regret form
  2 sigma sqrt(2 ln 2n) is already 0.50 at n = 2, larger than the oracle best value at n = 2 (0.377).
  Source: `T1_sim.json` keys `bounds`, `A_independent`, `B_correlated_rho0.8`.
- A growing gap does not mean more candidates hurt. With unbiased, homoscedastic errors and i.i.d.
  candidates, true value of the chosen plan rises at every n (0.288, 0.353, 0.417, 0.479, 0.528 for
  n = 1, 2, 4, 8, 16) while the gap rises too (0.000 to 0.165). The rule "stop when the apparent gain
  is all curse" never fires; stopping then comes only from the cost per candidate (Russell-Wefald).
  Rise-then-fall needs heteroscedastic or heavy-tailed error, or error correlated with the plan
  (see prior work). Source: `T1_sim.json` key `A_independent`.

- The direction is backwards for a calibrated forecaster. If F equals the conditional expectation
  E[V | the forecaster's inputs], selecting on F has no curse at all, because E[V | F] = F; this is
  Smith and Winkler's own point about Bayesian estimates. Large stated uncertainty then means a large
  gap only when the forecaster is noisy, not when it is calibrated. Sibling evidence: the E3 hawk's
  toy gives a gap within noise of 0 for a calibrated E[v|x] up to n = 64, and 0.23 at n = 16 for a
  noisy, unbiased forecaster (`hawks/E3-sim.out`, made by `hawks/E3-sim.py`, not by this hawk). So the
  gap measures miscalibration conditional on the plan, not "uncertainty". T1 and E3 should share one
  harness rather than run twice.

So "the optimism gap grows with n" is guaranteed for any forecaster with nonzero error. Reporting it
as a result would be uninformative.

## 2. Hidden assumptions the policy violates

1. **Forecaster uncertainty is not its error.** A fixed-format P(success) = p carries Bernoulli
   variance p(1-p), which is aleatoric and does not drive the curse. The curse is driven by epistemic
   error, F minus the Bayes value given the evidence, which no single realised outcome reveals.
   Aggregate calibration (ECE) says nothing about error at the argmax. In the toy, even when the stated
   uncertainty is a perfect monotone of the true error sd, it correlates only 0.49 with |error| (0.59
   with the selected error). At a realistic tracking of 0.3 it is 0.15. Source: `T1_sim.json` key
   `D_hetero`. Gleave and Irving found the same for LM reward models: ensemble epistemic uncertainty
   is "only weakly correlated with model error" (arXiv 2203.07472).
2. **Shared misbelief (correlated errors).** All candidates come from one situation report and one
   forecaster, so errors share a common part. At rho = 0.8 the gap falls from 0.165 to 0.039 at
   n = 16 and true value is higher (0.581 vs 0.528). Any sigma-based bound is about 9x loose. The
   common part still biases the level of value without growing with n, so it matters for "commit vs
   keep thinking" but not for the curse. Source: `T1_sim.json` key `B_correlated_rho0.8`.
3. **Adaptive proposal.** GOAL.md's policy reads forecasts and then proposes more candidates. That
   is hill-climbing on F, not best-of-a-fixed-set, and the sqrt(log n) analysis does not cover it.
   With proposals made near the current forecast-best, the gap at n = 16 is 0.221 against 0.160 for
   i.i.d. proposals, and true value is lower (0.339 vs 0.394). This is Gao et al.'s
   BoN-versus-RL distinction inside one deliberation. Source: `T1_sim.json` keys
   `E_adaptive_proposals`, `E_iid_proposals`.
4. **Endogenous n (optional stopping).** The policy stops when something looks good, so n is chosen
   by the forecasts. With "stop at the first F > 0.55", the logged gap is flat at about 0.155 for
   n = 1 to 8 and lowest at n = 16 (0.101). That is the opposite of the exogenous curve (0.000 to
   0.165). Any "optimism gap vs candidates considered" plotted from the policy's own logs is
   confounded by difficulty and by the stopping rule itself. Source: `T1_sim.json` key
   `F_optional_stopping`.
5. **Non-stationarity.** Signal 2(d) corrects forecasts of selected plans first, and GRPO on realised
   reward teaches the policy its own implicit discount of the forecasts. So the selection rule is not
   argmax F, and the gap drifts during training. Measure only at frozen checkpoints and log the
   actual selection rule.
6. **Bias vs curse.** A forecaster that is simply optimistic (+0.05) shows a gap at n = 1. Only the
   argmax-minus-random-pick difference isolates the curse (0.216 - 0.049 at n = 16). Source:
   `T1_sim.json` key `C_biased_plus0.05`.
7. **Duplicates and power.** LLM candidates repeat, so count distinct plans. With n <= 8 and binary
   outcomes, the curve differences are a few hundredths, which needs thousands of episodes unless
   outcome noise is removed (see the reshape).

## 3. Prior work that already answers most of it (fetched 2026-10-03)

- Smith and Winkler 2006, "The Optimizer's Curse: Skepticism and Postdecision Surprise in Decision
  Analysis", Management Science 52(3):311-322, https://doi.org/10.1287/mnsc.1050.0451 (verified via
  Crossref). The curse and the Bayesian shrinkage fix.
- Russell and Wefald 1991, "Principles of metareasoning", Artificial Intelligence 49(1-3):361-395,
  https://doi.org/10.1016/0004-3702(91)90015-C (verified via Crossref). The value-of-computation
  stopping rule.
- Hay, Russell, Tolpin and Shimony 2012, "Selecting Computations: Theory and Applications", UAI,
  https://arxiv.org/abs/1207.5879. Bayesian selection problems, finite sampling bounds for optimal
  metalevel policies, and a counterexample where the optimal policy never decides.
- Gao, Schulman and Hilton 2022, "Scaling Laws for Reward Model Overoptimization",
  https://arxiv.org/abs/2210.10760. The proxy-vs-gold curve, with different forms for BoN and RL. Verified
  from the PDF text (pypdf, 2026-10-03): R_bon(d) = d(alpha_bon - beta_bon d), R_RL(d) = d(alpha_RL -
  beta_RL log d), d = sqrt(KL), and KL_bon = log n - (n-1)/n computed analytically.
- Huang, Block, Liu, Jiang, Krishnamurthy and Foster 2025, "Is Best-of-N the Best of Them?",
  https://arxiv.org/abs/2503.21878. BoN "provably suffers from reward hacking when N is large".
  Their InferenceTimePessimism is scaling-monotonic, i.e. it does not degrade with N.
- Khalaf, Verdun, Oesterling, Lakkaraju and Calmon 2025, "Inference-Time Reward Hacking in Large
  Language Models", NeurIPS 2025, https://arxiv.org/abs/2506.19248. Rise-then-fall of true reward is
  "an inevitable property" of BoN-type mechanisms, and HedgeTune finds the optimal N. **This is the
  stopping rule T1 proposes to derive.**
- Coste, Anwar, Kirk and Krueger 2023, "Reward Model Ensembles Help Mitigate Overoptimization",
  https://arxiv.org/abs/2310.02743. Uncertainty-penalised BoN (WCO/UWO) "practically eliminates
  overoptimization".
- Gleave and Irving 2022, https://arxiv.org/abs/2203.07472. See hidden assumption 1.
- De Sabbata, Sumers, AlKhamissi, Bosselut and Griffiths 2024, "Rational Metareasoning for Large
  Language Models", https://arxiv.org/abs/2410.05563 (fetched). An LLM trained with a reward that
  builds in the value of computation, penalising reasoning that does not help the answer (20-37% fewer
  tokens at equal accuracy). This is the learned-VOC stopping rule for LLMs, minus the forecaster.
- Manheim and Garrabrant 2018, "Categorizing Variants of Goodhart's Law",
  https://arxiv.org/abs/1803.04585. Regressional Goodhart is this curse. The paper's naming of it is
  from recollection; the abstract page does not name the variants.

What is not covered there, and is the only part worth the night: the gap model **learned from
realised outcomes only** (GOAL.md signal 4), used as a stopping and shrinkage rule for a forecaster
that is **mask-protected from reward**, compared with HedgeTune, pessimism and ensemble-penalty
baselines at equal forecaster-call budget, and fused against protected.

## 4. Reshape (exact change)

Replace "derive and test the stopping bound" with an exogenous-n evaluation harness:

0. **Make stopping matter.** Add an explicit cost c per forecast block to the evaluated objective
   (e.g. c in {0.005, 0.01, 0.02} of the success scale), or a fixed token budget. Without it the
   optimal stopping point is n = max in every configuration we simulated (section 5), and the item
   reduces to the E3 curve.
1. **Truth without outcome noise.** The harness env already gives it: `ShipHunt.bayes_plan(plan)`
   (`harness/env/shiphunt.py`) returns the exact P*(success | evidence, plan) by enumerating
   placements. The forecaster's epistemic error is epsilon_i = F_i - P*_i per candidate. No branching
   rollouts, no reliance on stated uncertainty, and no Bernoulli noise. This is required, not
   optional: section 5 puts the curse at n = 16 at 0.02-0.04 with se 0.003 over 400 states using P*;
   with realised 0/1 outcomes the se at 400 states is about 0.02, so the effect would not be seen.
   Use presets easy and medium (full enumeration of plans for the oracle); hard needs subsampled
   plans (section 5 caveat).
2. **Exogenous n.** At frozen checkpoints (pre-RL, mid, end; fused B0 and protected arm), draw a pool
   of 16 candidates per held-out state, dedupe, and evaluate nested subsets n in {1, 2, 4, 8, 16}.
   Use two proposal modes on the same states: (a) i.i.d., all plans proposed before any forecast is
   read; (b) adaptive, the policy's own read-then-propose loop with n forced.
3. **Cheapest control: random pick.** For every n report gap(argmax) - gap(random pick) on the same
   pool. This separates the curse from plain forecaster bias at zero extra forecaster calls. Also
   report the endogenous-n curve from the policy's own logs next to it, so the optional-stopping
   artefact is visible rather than mistaken for a result.
4. **Stopping rules compared at equal forecaster calls**, scored by true P* of the committed plan:
   fixed n tuned on validation; the learned gap model (signal 4); Smith-Winkler shrinkage with sigma
   from the forecaster's stated uncertainty; LCB pessimism (Huang et al. 2025 style); a HedgeTune-style
   tuned n (Khalaf et al. 2025); ensemble WCO (Coste et al. 2023) if two forecaster seeds exist.
5. **Test the hidden assumption directly.** Spearman(stated uncertainty, |epsilon|) and
   Spearman(stated uncertainty of the selected plan, epsilon_selected).

CPU only, using forecasts from checkpoints that E1/E3 already produce. No new GPU spend beyond
inference on ~500 states x 16 candidates per checkpoint.

**Kill conditions for the "bounded by forecaster uncertainty" version** (keep only the learned-gap
version): Spearman(stated uncertainty, |epsilon|) < 0.2, or Smith-Winkler-with-stated-sigma no better
than fixed tuned n. **Kill the whole item** if the learned gap model does not beat a fixed tuned n and
HedgeTune by more than the seed sd at equal calls, or if the fused-vs-protected gap difference at
n = 8 is within seed sd. In either case the stopping story adds nothing to the LIR claim.

What would have to be true for the original to be worth running as stated: a lower bound on
change-in-gap in terms of the forecaster's stated uncertainty that is tighter than the value range at
the n the policy actually uses. That requires stated uncertainty to track epistemic error at the
argmax, which hidden assumption 1 and the cited evidence make unlikely.

## 5. Check on the harness's own env (ShipHunt), added in v2

`hawks/T1_env_sim.py` -> `hawks/T1_env_sim.json`, log `hawks/T1_env_sim.out` (numpy 2.5.3, seed 1,
400 states per preset, single core, about 3 min). Presets from `harness/env/shiphunt.py`. Plans are
cell sets of size plan_len (need_hits success depends only on the set). Exact P* by enumeration;
for hard, 3000 of 12650 plans are sampled, so its "oracle" is over the sample (greedy can exceed it).
Forecaster error has two parts: belief-level misbelief (posterior log-weights + N(0, s^2), shared by
every candidate, the situation-report error) and per-plan forecast noise N(0, t^2). Proposers: iid
uniform plans, or "policy" (softmax over the forecaster's own F at temperature 0.05, i.e. proposes
what it believes is good). "curse" = gap(argmax) - gap(random pick), same candidate pool.

Findings (numbers from `T1_env_sim.out`):
- **Search has headroom, but small.** The plan made from the top cells by exact cell probabilities
  is optimal in only 4% (easy) and 7% (medium) of states, because adjacent cells are covered by the
  same ship. Oracle P* vs greedy: 0.902 vs 0.828 (easy), 0.957 vs 0.916 (medium).
- **True value never falls with n.** In all 9 (preset, s, t) settings x 2 proposers, true P* of the
  chosen plan is non-decreasing from n = 1 to 16 (e.g. easy, s = 1, t = 0.05, policy proposer:
  0.794, 0.816, 0.829, 0.830, 0.831). No rise-then-fall. With free forecasts the stopping rule never
  fires; only a cost per forecast creates an interior optimum, which is why reshape step 0 exists.
- **Shared misbelief alone gives no curse under the policy's own proposals.** With s = 1, t = 0 the
  curse at n = 16 is -0.020 +- 0.004 (easy), -0.001 +- 0.001 (medium), 0.001 +- 0.001 (hard). The policy
  proposes inside its own misbelief, so argmax F within that set does not select on error. With iid
  proposals the same misbelief gives a curse of 0.061 (easy). So the curse in this design comes from
  per-plan forecast error (phrasing, plan-specific slips), not from the belief error that the LIR
  masks are about. A T1 result about "forecaster uncertainty" will mostly measure per-plan noise.
- **The effect size is small.** With per-plan noise t = 0.05 the curse at n = 16 under the policy
  proposer is 0.034 (easy), 0.034 (medium), 0.038-0.042 (hard), se about 0.003. That is the whole
  quantity the stopping bound is about. The fused-vs-protected difference in it will be smaller still,
  so kill condition "fused-vs-protected gap difference at n = 8 within seed sd" is likely to trigger;
  eurisko should expect T1 to end as a negative or null result unless the E3 forecaster is much noisier
  than t = 0.05.
- **Duplicates.** The policy proposer at temperature 0.05 yields 10.3 distinct plans out of 16 on easy
  (14.8 on medium). An LLM proposer will likely repeat more; count distinct plans for n.
- The variance-decomposition key `shared_error_var_frac` is 0.00 everywhere: perturbing the posterior
  does not shift the mean forecast across all plans (it reorders them). Not a measure of error
  correlation between selected candidates; ignore it.

Net for eurisko: the T1 measurement is cheap to bolt onto E3 (CPU only, uses `bayes_plan`) and should
run there with a cost per forecast and the random-pick control, as one harness. As a standalone theory
item with a "bound by forecaster uncertainty", it is vacuous at the scales the env produces.
