4. **Held-out transfer: ARTEFACT of construction.**
   - desc_j encodes per-factor loading norms (`B.norm(dim=1)`) and log sigma, not the signed 8 × 8 loadings, and the observations are rotated. Even an exact Bayesian given the description cannot decode a new source; the best it can do is ignore it.
   - The comparator is unfair: "extremizing 0.05-0.06" uses exact posteriors that know the held-out loadings.
   - The fair numbers, on the same held-out test episodes (alpha 0 / 0.5 / 1; my run reproduces the README's ext_exact 0.0549 / 0.0525 / 0.0589): Bayes ignoring held-out sources gets 0.016 / 0.017 / 0.016, and extremized exact forecasts that ignore them get 0.070 / 0.068 / 0.065.
   - So losing the unreadable sources costs only about 0.016 nats. The learned arms (0.08-0.13) remain worse even than the fair extremizing, so the failure is self-inflicted: forecasters do not discount sources they cannot read, and out-of-distribution descriptions produce confident garbage. That is a robustness bug (fix: train with unknown-source dropout), not a limit on transfer.
   - The proposed next step (randomize loadings per episode) is learnable only if desc_j carries B_j and sigma_j in full.
5. **sigma-3 key worse than no key: ARTEFACT (optimization).** The model class contains the no-key model (zero key weights), and every episode is fresh, so it cannot overfit. The population optimum is therefore <= no key. In the val logs the sigma-3 arm plateaus (alpha 1: 0.5343 at mid-run, 0.5314 at the minimum; no key goes 0.5258 to 0.5211), and sigma 3 was never in the 24k probe. Likely cause: key inputs with sd ≈ 3.5 are concatenated with lo/4 (sd ≈ 0.5) into one embedding. Fix: standardize the inputs or route the key only through attention, initialise from the no-key model, and run 4x steps. Until then, write "not yet learned to ignore", not "noisy keys hurt".
