## A. E1 OwnSensorInfoGLSHead
- **Hard-coded vs learned: artefact (as a learning result).** F:466-483 builds Sigma = B_hat B_hat^T + diag(sig2_hat) + gamma R_k over every prefix agent, then P = I + A^T Sigma^-1 A, h = A^T Sigma^-1 s, mean = P^-1 h. That is the exact E1 posterior (envs.py gaussian_global). The prior N(0, I), the linear-Gaussian likelihood and the low-rank-plus-diagonal noise are all designed. F:438-443 also computes the own-sensor natural parameters A^T R^-1 A and A^T R^-1 s analytically. What is learned at full: a row MLP that maps the key row (A_k row, B_k row, log sig_k; F:310-314) to B_hat (r_lat = 4 >= the true r = 2) and sig2_hat, plus gates and a mix weight. Bayes is reached with B_hat = B and sig2_hat = exp(2 log sig): a near-identity map. All cross-agent coupling happens in the hand-written Sigma, not in attention. Evidence: without the GLS layer the same net stays at 0.830 (tt_own_info_all, full).
- **Privileged inputs: holds (no leak).** B_i, A_i and log sig_i are in key.full by the benchmark's definition of visibility full (envs.py:300). in_dim 47 is the same for the bar and the arm (result.json extra.arms_meta). The number of factors is not passed in (r_lat = 4 is a designer choice). It is visible from the key width, though.
- **Bug: holds.** At none, in_dim = 34 >= 27, so `has_prov_key` (F:263) is true. The parser then reads report mean and precision entries (x[14:27]) as "A_k, B_k, log sig". There is no leak, but the row features at none are mis-structured and not row-equivariant.
- **Fairness vs the bar: partly.** Same tokens, the same fresh episodes (tok_tr[:3000*512], each used once), lr 1e-3, wd 1e-2, OneCycle and 3000 steps. But the 1.09 bar is 64x3. The size-matched 128x4 bar gives 0.956 (full). The 0.0031 arm uses 6000 steps; the bar improves to 0.852 at 12k steps (e1floor). The comparison is "solver given the model class" against "generic transformer", not like for like.
- **Oracle labels: holds.** Only tt_own_info_distill has uses_oracle=True, and it is tagged [ORACLE CEILING]. All GLS arms train on the truth theta with Gaussian NLL (F:614).
- **README from JSON: holds.** Rerunning `scripts/render_tt_z9_e1_readmes.py` on origin/main gives no diff (296/296 numbers verified). Caveat: most per-seed values come from a parsed run log (seed012_partial.txt, rounded to 4 dp), e.g. full GLS [0.0082, 0.0041, 0.00487]. They match the log.
- **floor_none: partly.** 0.6436 marginalises the rotation only, with sigma known, and inserts the true B as draw 0 of 256 (F:156-171). The same quantity on e1floor, rotation only, is 0.635 [0.586, 0.681], so they agree. The correct floor at none (R_i does not determine sigma_i) is 0.685 [0.636, 0.735]. The floor for a Gaussian output is 0.708. The GLS gap at none is therefore about 0.09-0.13 nats, not 0.17. GLS at none (0.816) is the same as sum_logodds (0.827); it adds nothing.
- **noisy 0.31: cannot verify against optimum.** No floor exists for noisy, so "60% cut" is only relative to sum_logodds.
**Must fix (A):** (1) In the README, label the GLS arms "designed solver (GLS given the model class)", not "matching exact Bayes"; the learned share is reading B and sigma from the key. (2) Run GLS with attn_layers=none: if it stays at about 0.005 at full, attention does no aggregation here. (3) Fix the has_prov_key test (key it on visibility, not on in_dim >= 27) and rerun at none. (4) Replace floor_none with 0.685 (or quote both) and add the 0.708 Gaussian floor. For Kelvin's bar, the result that counts is still the generic transformer: 0.85-1.09 vs Bayes 0 at full.

## B. Compression v2
- **Bit accounting: holds.** tanh gives |s| <= 1 and the noise variance is 1/3 (C:1319). The 1 bit per dimension from 1/2 log2(1+3) is an upper bound; with an amplitude limit the capacity is lower still. Eval sends sign(.), which is exactly b bits, and Channel(b).send checks this (C:1543). The decoder sees only the messages (C:1378-1382).
- **Matched arms: partly.** Same _net_v2 decoder, data and optimizer. The decoder gets S steps in both arms (self: S encoder steps + S decoder steps; aware: S end to end). Only the aware variants get the curriculum pools (2 x 30k extra episodes on k = 2 and 3) and the auxiliary loss.
- **Leak: partly (for the headline).** The aux loss (C:1394-1405, 1496-1502) trains on prefix parities b1, b1^b2, b1^b2^b3 of the latent bits oracle.w, in the same order as the one-hot bit index in the token. That is supervision on the simulator's latent structure beyond Y; the README calls it "training labels only". Kelvin's question (B), "train only on the final token?", is exactly what this bypasses. The curriculum uses Y labels only, but it encodes the designer's knowledge that the task is a parity. The headline +0.068/+0.242/+0.338 is all aware_curr_aux. Label-only (plain aware, Gaussian channel): **+0.065 / +0.108 / +0.228**, regret 0.392 / 0.349 / 0.229.
- **Synergy by construction: holds, and should be stated.** In Z9 (k = 4), an agent with p = 2 readings has zero mutual information with Y. The self-summary target is therefore independent of its input, its encoder collapses (1-2 distinct symbols) and the self arm sits at the prior, 0.457, in every cell. That comes from Z9 itself, not from the p2 wrapper. So the Z9 "gain" is aware minus prior. The tests that matter: raw_code reaches 0.000 at b >= 2 and learned aware gets 0.215/0.119, so it fails Kelvin's bar. A frozen random encoder + trained decoder arm (not run) would be a fairer non-aware control.
- **E2/E3 ties: partly.** For the Gaussian channel, every |gain| <= 0.006. But E3-sybil b=1 is -0.006 with all 3 seed CIs below zero, so self-summary wins slightly there.
- **README vs JSON: holds for the gains** (recomputed from learned_v2_*.json: e.g. Z9 b2 curr_aux +0.242, E2 b1 -0.003). The "steps to escape" column uses 0.9 x the prior KL, recomputed from the curves. The stored `steps_to_escape` field and the docstring use 0.5 (C:1547). The JSON files have no harness/commit field and are not in the repo.
**Must fix (B):** (1) Lead with the label-only gains; tag the aux arms "latent-label supervision". (2) State that self-summary is null on Z9 by construction; add the random-encoder control and an uncompressed full-context transformer anchor on Z9-p2 (currently n/a). (3) Make the escape threshold consistent; commit the JSON with the harness commit.
