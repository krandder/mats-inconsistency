# Question-dependent agents: first results (opus-mats builder, 2026-10-23)
Code: work/qagents/ (q_env, q_ref, q_learn, q_summary; PREREG.md). Results: work/qagents/results/ (69 runs, summary.txt).
Design: outbox/question-dependent-agents-design-2026-10-23.md, with the design-fit review's fixes:
- Q-only learned arm (agent gets q, no consensus), a consensus-aware closed-form reference (3s), and a keyed one-shot reference (4k).
- The world was changed so that Bayes is exact with R latent. A smoke run showed R_i is barely identifiable: local P(true R_i | x_i) is 0.07. Changes: orthonormal U, V, W, and a product-form Zipf prior on R.
- So Bayes (1) = P(Y | all x, keys, q). The true-R oracle is reported as a bound.
- a = 2 was chosen by the pre-registered rule on separate selection episodes; it was the only a with Bayes(1) <= 0.6 x prior.
Tests: 13/13 pass (true-R and latent-R Bayes vs brute force to 1e-9; local posterior; R prior; Monte Carlo calibration; keyed decoder; (3s) = (3) when nothing is dropped).

Sanity cell (b=4, sigma 0.5, nu 1; dev 4000 episodes; Y log-loss in nats; mean ± se over 3 seeds, unconditional):
prior 0.576 | learned one-shot 0.528±0.002 | q-only 0.411±0.007 | query 0.463±0.009 | (3) 0.432 | (3s) 0.434 | (4) 0.530 | (4k) 0.533 | bar 0.338±0.005 | Bayes(1) 0.305 | oracle true-R 0.225

Sweep, learned one-shot / q-only / query vs references (3) / (4):
- nu=0, b2: 0.550 / 0.440 / 0.485 vs 0.491 / 0.555. b4: 0.528 / 0.410 / 0.470 vs 0.432 / 0.530. b8: 0.510 / 0.395 / 0.455 vs 0.411 / 0.485. Bar 0.348.
- nu=1, b2: 0.549 / 0.440 / 0.493. b4: 0.528 / 0.411 / 0.463. b8: 0.504 / 0.392 / 0.448. Bar 0.338.
- Wide (32 floats, about lossless): one-shot 0.443 (nu 0) and 0.466 (nu 1); query 0.415±0.022 (nu 1).
- Bayes and the references do not depend on nu: V is orthogonal to U, so g is a pure distractor.

What it shows:
1. Knowing the question is worth a lot. The query gain (one-shot minus query) is +0.055 to +0.066 nats in all 6 (nu, b) cells, and positive in 18/18 seed pairs.
2. The consensus adds nothing measurable here.
   - The query arm gets q plus the consensus, yet it is worse than q-only by 0.045-0.060 nats in every cell (18/18 pairs).
   - Its val loss is still falling at 30k steps, and it learns more slowly (9 sequential aggregator passes per step). Because its inputs are a superset of q-only's, this is a learning cost, not missing information.
   - The closed-form consensus-aware protocol (3s) also equals (3) within ±0.008.
   - The toy itself is why. 47% of agents read no S bit and 44% read one, so once q is known, b bits are enough and there is nothing for the consensus to steer.
   - So Kelvin's "query before compression" is supported in its question part. The consensus-state part is untested by construction.
3. Learned one-shot sits on its closed-form reference (4) at b2 and b4; at b8 it is worse (0.504-0.510 vs 0.485).
   - Stall rule (closes < 20% of the prior-to-Bayes gap): one-shot b2 and b4 are stuck 6/6 per nu, as is the reference (4) itself. That is the bottleneck, not training.
   - No other run is stuck (0/57).
4. No message arm reaches the bar. The best, q-only b8, is +0.054 over the bar, and wide one-shot is +0.13. The bar is +0.03 to +0.04 over Bayes(1).
   - The best checkpoint is at 26k-30k steps in every run, so nothing is converged.
5. Dilution: S is fully read in only 59% of episodes. Parity with an unread bit sits at ln 2 for everyone.
   - On fully-read parity (b4, nu 1): one-shot 0.672, query 0.583, q-only 0.454, bar 0.268, Bayes 0.200.

Caveats: (3), (3s), (4) and (4k) are achievable protocols, not optima (k-means codes, naive product, Platt calibration). (4k) is weaker than (4) because R is poorly identified (MAP R from x is right 17% of the time). The amplitude a was picked from 3 values. Stall counts are not filtered.

Spend: $6.57 at the $0.87/h ceiling (GPU-LOG, VM age), of the $18 cap. About $0.45 of that went to three failed spot attempts (stockout or preemption), after which the runs used on-demand L4s.

Next (proposed, not run): make the consensus matter. Options are |S| of 4-6 with redundant readers, so later agents should skip bits already settled, or agents that read more of S. Also warm-start the query arm from q-only, to separate learnability from information.
